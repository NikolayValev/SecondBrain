# SecondBrain Architecture Reference

## Runtime Layering

1. App wiring + lifespan lives in `app/main.py`.
2. HTTP handlers live in `app/api/routes/*`.
3. Request/response contracts live in `app/api/models/*`.
4. Business logic lives in `app/services/*`.
5. Core storage/indexing logic lives in `app/db.py`, `app/indexer.py`, `app/parser.py`, `app/vector_search.py`.

Keep route handlers thin; push behavior into service modules.

## API Domains

- `system`: health, stats, config (`app/services/system_service.py`)
- `search`: FTS and semantic search (`app/services/search_service.py`)
- `files`: file/tag/backlink access (`app/services/file_service.py`)
- `rag`: ask + embedding generation (`app/services/rag_service.py`)
- `inbox`: inbox processing and folder scans (`app/services/inbox_service.py`)
- `indexing`: synchronous and background indexing (`app/services/indexing_service.py`)
- `sync`: SQLite -> PostgreSQL sync APIs (`app/services/sync_api_service.py`)
- `conversations`: conversation/message CRUD (`app/services/conversation_service.py`)

## Storage Topology

- SQLite (`app/db.py`) is primary and authoritative at runtime.
- Tables include files/sections/tags/links/chunks/embeddings/conversations/messages + FTS5 virtual table.
- PostgreSQL (`app/db_postgres.py`) is an optional mirror used for Prisma/Next.js read paths.
- Sync orchestration runs through `app/sync_service.py`.

## RAG and Provider Flow

1. Retrieval strategy is selected in `app/rag_techniques.py` (`basic`, `hybrid`, `rerank`, `hyde`, `multi-query`).
2. Embeddings are generated by `app/embeddings.py`.
3. Vector retrieval runs in `app/vector_search.py` (brute-force cosine over stored vectors).
4. Answer orchestration and streaming SSE live in `app/services/rag_service.py`.
5. Provider abstraction lives in `app/llm.py` with `openai`, `gemini`, `ollama`, `anthropic`.
6. Embeddings can use `EMBEDDING_PROVIDER` override independent of `LLM_PROVIDER`.

## Conventions

- Most modules expose singleton instances for production paths.
- Async boundaries are important for PG and provider I/O paths.
- Embeddings are stored as packed float bytes in SQLite; preserve compatibility.
- API key middleware protects all endpoints except the explicit public set.

## Risk Hotspots

- Route/model/service drift (contract updated in one layer only).
- Conversation identity assumptions (SQLite IDs vs mirrored PG IDs are not guaranteed to match).
- Sync dedup behavior for conversations (best-effort key matching by session/timestamp).
- Changes to embedding dimensions/serialization and pgvector mirror behavior.
- Any logic touching FTS query sanitization or path normalization.
