# RAG Guide

This guide reflects the current RAG implementation used by:

- `POST /ask`
- `POST /search` (semantic mode)

## Current Pipeline

1. Retrieval strategy selected from `app/rag_techniques.py`.
2. Query embedding generated via `app/embeddings.py`.
3. Candidate chunks retrieved via `app/vector_search.py`.
4. Context assembled by technique implementation.
5. Response generated by provider in `app/llm.py`.
6. API orchestration handled by `app/services/rag_service.py`.

## Supported Techniques

| ID | Name | Summary |
|---|---|---|
| `basic` | Basic RAG | Semantic retrieval only |
| `hybrid` | Hybrid Search | Semantic + FTS5 fused via RRF |
| `rerank` | Re-ranking | Candidate retrieval + cross-encoder reranker |
| `hyde` | HyDE | Hypothetical answer embedding retrieval |
| `multi-query` | Multi-Query | Query expansion and merged retrieval |

Use `GET /config` to get the live available technique list.

## Prerequisites

RAG quality depends on indexing + embeddings.

1. Index notes (`POST /reindex` or `POST /index`).
2. Generate embeddings (`POST /embeddings/generate`).
3. Verify embedding stats (`GET /embeddings/stats`).

## Ask API

## Non-stream mode

```bash
curl -X POST "http://127.0.0.1:8000/ask" \
  -H "Content-Type: application/json" \
  -d "{\"question\":\"What are my notes about PostgreSQL sync?\",\"rag_technique\":\"hybrid\",\"include_sources\":true}"
```

## Stream mode (SSE)

Send `stream: true`:

```json
{
  "question": "Summarize recent inbox automation notes",
  "stream": true
}
```

SSE events:

- `type=source` (optional; emitted first)
- `type=token` (incremental text chunks)
- `type=done` (final event with `conversation_id` and `model_used`)

## Provider and model selection

`/ask` accepts:

- `provider`: `openai`, `gemini`, `ollama`, `anthropic`
- `model`: optional override
- `rag_technique`: retrieval strategy id

If omitted, defaults come from runtime config.

## Conversation behavior

- RAG exchanges are persisted to SQLite conversations/messages.
- `/ask` accepts `conversation_id` as string.
- History lookup in current code requires a numeric conversation id value.
- Use conversation APIs (`/conversations`) for explicit conversation lifecycle.

## Embedding behavior

- Embeddings are stored in SQLite as packed float bytes.
- Vector search is brute-force cosine similarity over stored embeddings.
- If PostgreSQL sync is configured, embedding writes are mirrored best-effort.

## Tuning tips

- Start with `hybrid` for general use.
- Try `rerank` when semantic relevance is weak and reranker dependencies are available.
- Try `hyde` or `multi-query` for ambiguous questions.
- Keep notes semantically rich (clear section headings and focused paragraphs).

## Troubleshooting

- No answers or weak answers:
  - Verify `GET /embeddings/stats` has non-zero `embedding_count`.
  - Re-run indexing and embedding generation.
- Provider errors:
  - Verify `/health` provider availability and API key config.
- Slow responses:
  - Streaming mode improves perceived latency.
  - Large vaults may need tighter retrieval limits or faster local models.
